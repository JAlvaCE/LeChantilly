# ADR — Owner-first Studio (v0.13 foundation)
## Decision
A mobile-first web app for the owner, separate from the customer journey. Temporary practice URL /mi-negocio.html; production target private Studio under a dedicated business origin. Keep static public storefront and existing REST backend separate. PWA installability, icons and offline behavior require later testing; do not cache private data or authentication responses. No technical menus, JSON, dashboards with fictitious metrics or public registration.
## Owner experience
Invite once to her own email; passwordless email code and managed second factor (prefer passkey if provider supports suitable flows, otherwise TOTP with guided enrollment). Open bookmark/shortcut; sign in when needed. Everyday tasks: recipes, cost, agenda, orders, ingredients, finances. Three-step guided capture, plain Spanish, defaults only when justified, explain changes and show confirmation. No public access to actual information. No email or password collected on the demo.
## Infrastructure and activation
Supabase candidate: managed Auth + PostgreSQL. No integration installed or project provisioned; no credentials or owner account configured. Prepare schema migration for a dedicated project, run only after confirming project owner and plan. Disable public signup; invite verified owner, set approved redirect origins, configure reliable transactional SMTP if needed, use managed SDK and server-side session adapter; authorization by verified user UUID and AAL2 at every protected route. Cookie sessions HttpOnly/Secure/SameSite, CSRF/origin validation for writes, server-side authorization and RLS, fail closed on unavailable provider. No service key in browser. No owner registration through public endpoints. Restrict DB schema and grants, transactional writes, optimistic revision and audit, backup and tested restore. Keep real recipes out of public Git. Do not activate on Hobby commercial hosting. Confirm compliant hosting, backup retention, cost and transfer ownership with owner before production. 
## Migration scope
database/migrations/001_owner_recipe_drafts.sql is an unexecuted foundation, owner allowlist default inactive; RLS requires uid + aal2 + active membership. Only draft fields and archive; not full ingredient/recipe ERP. No application API or auth integration activated. Test in staging: anon, AAL1, inactive member, different user, owner MFA, forbidden owner_id/status/revision writes and deletion, revoked member, simultaneous edits, backups and restore. SQL needs runtime validation. No real data until gates approved.
## Acceptance
Owner can find and complete first task from mobile without developer help; observed usability test, keyboard/focus, responsive visual check, auth and MFA enrollment/recovery, two-account isolation, logout, session expiration and error handling, no private cache, database backup/restore, no charges without approval. Current demonstration is not authenticated and cannot save data.
