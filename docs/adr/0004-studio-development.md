# Studio de desarrollo — incorporación segura
Portal independiente apps/studio. Preview Vercel protegido, sin promoción a producción. Clave pública de Supabase en variables Preview, sin service role. GET /api/studio verifica proyección pública. Práctica temporal sin guardar ni enviar entradas. BFF mismo origen, cookie Secure/HttpOnly/SameSite=Strict de máximo 15 minutos, sin refresh, CSRF por Origin, límites de cuerpo y errores genéricos. Cada acción verifica usuario con Auth y contexto RPC; MFA obligatorio para leer/escribir. OTP solo para correo previamente invitado con create_user:false. No activar acceso real hasta verificar cierre de registro, plantilla de correo OTP, SMTP/entrega, identidad y correo de propietaria, MFA TOTP, recuperación y rate limits. Configurar LC_STUDIO_OWNER_EMAIL y LC_STUDIO_AUTH_ENABLED=true solo en Preview tras pruebas. No se han modificado ajustes Auth ni creado cuentas. Probar sesión real, caducidad/logout/revocación, recuperación de inscripción incompleta, concurrencia real, backups y seguridad de sesiones antes de activar. No almacenar datos reales. Fotos, pedidos y recetas completas pendientes. Previsualización local no equivale a storefront publicado. Publicación usa RPC transaccional; el storefront comercial sigue intacto. Para producción separar hosting autorizado y validar usabilidad con propietaria.
